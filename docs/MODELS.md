## 1. Passive Liveness: MiniFASNet (V2 and V1SE)

### Architecture Reference
- Origin: [Silent-Face-Anti-Spoofing](https://github.com/minivision-ai/Silent-Face-Anti-Spoofing)
- Output: 3 class logits:
  - Class 0: 2D Spoof (printed photo, digital screen, cut mask)
  - Class 1: Real / Live face (primary operational target)
  - Class 2: 3D Spoof (silicone mask, plaster model, mannequin)
- Classification function: Softmax over the 3 logits; score evaluated is the probability of Class 1.

### Cropping Specifications
- **MiniFASNetV2**: Crop scale factor = `2.7` around the detected face bounding box.
- **MiniFASNetV1SE**: Crop scale factor = `4.0` around the detected face bounding box.
- **Bounding Box Sizing**:
  - The detector bounding box is optionally expanded by `boxExpansion` (default `1.0`).
  - If the scaled box exceeds image boundaries, scale reduction is applied:
    $$\text{effectiveScale} = \min\left(\text{targetScale}, \frac{\text{imageHeight} - 1}{\text{boxHeight}}, \frac{\text{imageWidth} - 1}{\text{boxWidth}}\right)$$
  - The box is centered on the face box and shifted inside the image boundaries without stretching.
- **Sampling**: Resized to 80x80 using bilinear interpolation directly from raw camera frames.

### Preprocessing Specifications (`PassivePreprocessConfig`)
- Channel Order: BGR (original Silent-Face-Anti-Spoofing specification)
- Pixel Range: Raw `[0.0, 255.0]` float values without division by 255.0
- Normalization: Mean `[0.0, 0.0, 0.0]`, Standard Deviation `[1.0, 1.0, 1.0]`
- Real Class Index: `1`
- Softmax Applied in Post-Processing: `true` (model produces unnormalized logits)

### Calibration & Verification Protocol
Because third-party ONNX model exports can vary in channel ordering and value scaling, use `tools/verify_passive.py` to evaluate your target dataset:

#### 1. Full-Frame Dataset Evaluation Mode
```bash
# 1. Install prerequisites
pip install onnxruntime opencv-python numpy

# 2. Organize sample images
dataset/
  real/
    employee_01.jpg
    employee_02.png
  spoof/
    phone_screen_01.jpg
    paper_photo_01.jpg

# 3. Run verification tool
python3 tools/verify_passive.py --dataset dataset/ --threshold 0.85 --csv results.csv
```

#### 2. Precropped Device Crops Evaluation Mode (`--precropped`)
To evaluate the exact 80x80 RGB crops generated by the real Flutter device pipeline:

1. In the developer app, navigate to `/dev/passive`.
2. Select an evaluation scenario label (`live_face`, `video_on_phone_fullframe`, `video_on_phone_bezel_visible`, `photo_on_phone`, `printed_photo`, `other`).
3. Tap **Record Crops** to capture 80x80 BMP crops for each sampled frame to `<appDocDir>/eval_crops/<label>/`.
4. Tap **Share** to export the captured crop directory and CSV to your workstation.
5. Run:
```bash
python3 tools/verify_passive.py --precropped path/to/eval_crops/ --csv precropped_results.csv
```
This mode:
- Skips face detection and re-cropping; evaluates the exact crops produced on device.
- Tests all 5 preprocessing variants (`bgr_raw_255`, `bgr_0_1`, `rgb_raw_255`, `rgb_0_1`, `rgb_imagenet`).
- Evaluates both class-index interpretations (Class 1 as real vs Class 0 as real).
- Outputs per-scenario mean, std, min, and max probabilities.
- Prints sample raw logits to check for saturation.
- Generates a separation table comparing `live_face` against each spoof scenario, displaying the mean score delta and the optimal classification threshold.

**Current Status**: Default configuration uses original Silent-Face-Anti-Spoofing settings (BGR, raw 0-255, scale 2.7 for V2 and 4.0 for V1SE, index 1 as real). These parameters remain unverified on production captures until the `--precropped` report has been generated.

## 2. Face Recognition: SFace

### Architecture Reference
- Origin: OpenCV FaceRecognizerSF (based on SFace 2021Dec model)
- Input: 112x112 aligned face crop.
- Output: 128-dimensional feature embedding vector.

### Alignment Specifications
- 5-point Umeyama similarity transformation mapping detected facial landmarks (left eye, right eye, nose tip, left mouth corner, right mouth corner) to the canonical ArcFace 112x112 template:
  - Left Eye: `(38.2946, 51.6963)`
  - Right Eye: `(73.5318, 51.5014)`
  - Nose: `(56.0252, 71.7366)`
  - Left Mouth: `(41.5493, 92.3655)`
  - Right Mouth: `(70.7299, 92.2041)`
- Rotation constraint: Proper rotation enforced ($\det(R) = +1.0$) to reject mirror reflections.

### Preprocessing Specifications
- Channel Order: RGB
- Pixel Range: Raw `[0.0, 255.0]` float values without mean subtraction or division
- Embedding Post-Processing: L2 normalization to unit hypersphere ($||\mathbf{e}||_2 = 1.0$)
- Similarity Metric: Cosine similarity:
  $$\text{sim}(\mathbf{u}, \mathbf{v}) = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\|_2 \|\mathbf{v}\|_2}$$
- Recommended Cosine Threshold: `0.363` (configurable in `AppConfig.recognitionThreshold`).

### Verification & Calibration Protocol (`tools/verify_recognition.py`)

To verify that the app's preprocessing matches the OpenCV reference and to empirically calibrate the cosine threshold on real employees:

1. **Install Prerequisites**:
   ```bash
   pip install onnxruntime opencv-python numpy
   ```

2. **Evaluate Person Folders**:
   Organize images by person:
   ```text
   faces/
     person_a/
       crop1.bmp
       crop2.jpg
     person_b/
       crop1.bmp
       crop2.jpg
   ```
   Run evaluation:
   ```bash
   python3 tools/verify_recognition.py --dataset path/to/faces/ --threshold 0.363 --margin 0.10
   ```
   This computes genuine and impostor cosine similarity distributions, reports mean, min, and max, and evaluates FAR/FRR across a threshold sweep (`[0.25, 0.30, 0.35, 0.363, 0.40, 0.45, 0.50]`).

3. **Compare Direct Image Pair**:
   ```bash
   python3 tools/verify_recognition.py --compare image1.bmp image2.bmp --threshold 0.363
   ```
